## Root Cause

Both camera implementations had a **race condition**:

```
useEffect runs → getUserMedia() → stream ready → assign to videoRef.current
                                                  ↑ BUT videoRef.current is NULL here
                                                  (video element not mounted yet)
```

The `useEffect` with `[]` fires after the first render, but `getUserMedia()` is async — by the time the stream resolves, the component may have re-rendered and the ref may still be null on first assignment.

## Fix Applied

**Pattern changed from:**
```js
// ❌ Race condition — ref may be null when stream resolves
const stream = await getUserMedia(...)
if (videoRef.current) videoRef.current.srcObject = stream  // often null!
```

**To:**
```js
// ✅ Store stream in state, assign to ref in separate effect
const stream = await getUserMedia(...)
setCameraStream(stream)  // triggers re-render

useEffect(() => {
  if (cameraStream && videoRef.current) {
    videoRef.current.srcObject = cameraStream  // ref is guaranteed mounted now
    videoRef.current.play()
  }
}, [cameraStream])  // runs whenever stream changes
```

**Also added** `onLoadedMetadata` → `.play()` on both video elements to handle browsers that don't autoplay without an explicit `.play()` call.
